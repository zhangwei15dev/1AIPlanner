# 1AIPlanner

门店角色排班与人力分配小程序。Taro 4 + React 18 + TypeScript + Sass，一套代码同时编译到微信小程序与 H5。

核心思路：把「门店 → 角色 → 时段 → 人」摆到一张时间轴上，让店长一眼看出**哪个角色在哪个时段被占用、哪里缺人**，并把「一键排班」的结果实时落到这张视图里。

![总览](preview/overview.png)

## 功能

| 页面 | 说明 |
| --- | --- |
| 总览 | 门店切换（**列表 / 地图两种方式**）、周切换、覆盖率指标、**周排班矩阵（班次 × 日期）**、**角色 × 时间分配视图**（Outlook 风格，按天查看）、角色工时汇总 |
| 排班 | 一键排班、**Excel 模版下载 / 上传导入 / 计划表导出 / 自定义班表导入**、人力缺口清单、按班次分组的当日人员名单 |
| 员工 | 员工增删改、搜索 / 角色筛选、周工时进度条、主岗与通岗设置 |
| 助手 | 规则问答：一键排班、本周缺口、某天某班名单、角色分配、门店信息 |

### 门店选择：列表 / 地图

点顶部门店条打开选择面板，两种方式随时切换，默认列表：

- **列表**：门店名 + 区 + 地址 + 面积/层数/营业时间，点一行立即切换。
- **地图**：`Map` 组件铺开 6 家门店标记，标签常显；点标记或点地图任意位置都会吸附到**最近的门店**（haversine 计算），下方卡片显示该店信息与距当前门店的距离，确认后按「设为此门店」生效。

> 地图选点在小程序端完整可用；H5 预览里 `Map` 需要地图 key，会显示「地图选点在小程序端可用」的占位（业务逻辑不影响）。
> 标记图标是脚本生成的 2 个小 PNG（`src/assets/pin.png` / `pin-active.png`，各 ~0.4 KB），经 `copy.patterns` 拷到 `dist/assets/`。

### Excel 一键排班

排班页的「Excel 排班表」区块把线下表格和小程序打通，三步闭环：

1. **下载模版**：生成 `1AIPlanner-排班模版.xlsx` 并调起微信的文件预览，右上角菜单可转发/保存到微信，用 Excel、WPS、Numbers 编辑都行。模版里已经预填了示例员工与需求，改完直接上传就能看到排班。
2. **一键上传 Excel**：`chooseMessageFile` 从聊天记录里选 `.xlsx` → 解析 → 弹窗预览「解析到 18 名员工、16 条需求」→ 确认后**替换员工与需求并立即重排当周**。
3. **导出排班计划表**：生成含四个工作表的 `排班计划表-YYYY-MM-DD.xlsx`——`排班明细`（日期/星期/班次/时段/区域/角色/员工/工时，一行一班）、`按人汇总`（每人排班次数与周工时）、`缺口清单`、`汇总`（覆盖率、需求与实排数）。

模版结构：

| 工作表 | 列 |
| --- | --- |
| 员工 | 姓名、主岗、可通岗（顿号分隔）、技能等级(1-5)、周工时上限、周工时下限、状态（在岗/请假/培训） |
| 需求 | 区域、角色、班次、仅周末（是/否）——整表删掉就用内置默认需求 |
| 填写说明 | 取值枚举与规则说明 |

实现上没有引入 SheetJS（主包会多出近 1MB），而是用 **fflate（32KB）的 zip 能力 + 自研 240 行 xlsx 读写**：读时解压 `sharedStrings` 与 sheet XML，写时用 `inlineStr` 单元格。已用 `openpyxl` 交叉验证生成文件可被 Excel/WPS 正常打开，日期与数字保持原生类型。

### 自定义班表导入

门店如果已经有自己的排班表（Dayforce、飞书、Excel 手填都行），可以直接导进来生成计划，不用手抄：

1. 排班页「自定义导入班表」→ 从聊天记录选文件；
2. 解析后弹出预览：识别到多少人、时段跨度、岗位映射、区域识别情况，**日期可以手动修正**；
3. 点「导入并生成计划」，这一天的排班就按真实上下班时间落到 App 里。

支持两种常见结构，自动识别，不需要配置：

| 结构 | 识别方式 |
| --- | --- |
| 表格型 | 任意工作表，表头含「姓名 + 上班 / 下班」（列顺序随意，可夹带岗位、区域列） |
| 块状型 | A 列「员工003」+ 下一行岗位与「9:00上 - 6:00下」时段（复制班表这类导出） |

时间解析覆盖 `09:00` / `7:00 - 15:00` / `9:45上 - 6:45下` / `1:00下 - 10:00下` / Excel 时间单元格；同一人有多段（拆班）会自动合并成最早开始、最晚结束。

岗位按关键词映射到 7 个内置角色（店长 / 副店 / 导购 / 收银 / 仓配 / 教练 / 服务），**认不出的按导购处理**并在预览里说明；区域同理，表头没有区域列时会按内容猜一列（如 admin / 1F FL / w floater），猜不到就按一层零售区。

导入后的表现差异（避免和内置需求混算）：

- 总览页时间轴按真实时间自动扩展（07:00 开始的班表不会再被裁掉），色块位置与宽度对应真实上下班；
- 指标从「覆盖率 / 已排需求 / 缺口」切换为「排班人数 / 班次条数 / 覆盖区域 / 总工时」；
- 缺口清单替换为「该班表不参与内置需求对比」的说明；
- 导出计划表时，班次列写「自定义」、时段列写真实时间、工时按实际时长算。

### 两个核心视图

**周排班矩阵**：行是早/中/晚三个班次，列是周一到周日，单元格是当班人数；缺口会以「缺 N」红字标出，一眼看出周末哪里薄弱。

**角色 × 时间分配视图**：行是 7 个角色，横轴是 09:00–23:00。每个角色把自己的班次画成色块（位置=时间，高度=并行道），色块里直接写人员姓名，点开看区域与班次明细；「此刻」用红线标出。重叠班次按 Outlook 日历的方式自动分道，不会互相遮挡。

## 运行

```bash
npm install          # 独立部署时先装依赖
npm run dev:weapp    # 微信开发者工具打开项目根目录（miniprogramRoot = ./dist）
npm run dev:h5       # 浏览器调试
npm run typecheck    # tsc --noEmit
```

> 当前工作副本里的 `node_modules` 是指向相邻项目的软链，只为免装依赖；正式使用请执行 `npm install`。

首次启动会自动生成一周排班并落盘到本地存储（`aiplanner.v1`），之后的员工增删改和排班结果都会持久化。

## 排班算法

`services/scheduler.ts` 是纯函数，可单测：

1. `buildSlots(dates)` 按需求规则展开成一个个「人力槽位」（周末自动追加班次）。
2. 按日逐个槽位贪心选人，候选过滤条件：状态非请假、当日未排、周工时不会超上限、具备主岗或通岗资质。
3. 打分排序：主岗优先（通岗 +8）→ 培训中降权（+4）→ 负荷均衡（weekHours/10）→ 技能加分（-skill×0.4）→ 低于最低工时优先补足（-4）。
4. `summarize()` 对比需求与实际排班，产出覆盖率、缺口清单、每人周工时。

已知演示数据下的结果：需求 82 项、已排 79 项、覆盖率 96%，3 项缺口集中在周六/周日的「二层体验区 · 教练」，因为可用的 3 名教练周工时已经排满——这正是缺口视图和助手回答要说明的场景。
